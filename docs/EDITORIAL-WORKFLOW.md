# 现代释读与校勘工作规范（Stage 1）

## 五类内容不得混同

- **古籍转录**：三卷 JSON 的 text；固定电子来源，不等于历史校定本。
- **阅读句段**：splitSentences 根据现代标点得到的片段，不等于明刻本原句。
- **示范释读**：data/annotations.js 的作者自拟解释，全部 status=draft，不等于学术审稿通过。
- **逐句译文**：完整解释该句语法、句义与上下文；尚未完成全本。
- **校勘**：必须指定具体可靠刊本、卷页、异文，并记录审核者与证据。

## 条目模板

~~~js
{
  quote: "确实存在于指定 CXL 条目同一标点句段内的短引文",
  topic: "TOPICS 中的概念名",
  gloss: "自行撰写的现代释义；说明原话语境及适用限制",
  status: "draft",
  author: "可追踪的撰写者署名"
}
~~~

释义必须解释 quote 所属文字，不得凭概括性知识改变作者的论证方向。上句若为「来书云」中的提问，不可称作「先生曰」的直接观点。文本应保留原卷、篇、发言者与上下文，特别留意「四句教」相关讨论分歧。

## 从草稿到校审

独立撰写 → 逐字短引文比对 → 发言者归属判断 → 上下文核查 → 独立可靠刊本复核 → 对比异文与争议 → 审核者签名与证据 → 才允许标成 reviewed。

**目前尚无 reviewed 的持久化数据契约。** 未创建审稿证据和 schema 之前，不得将草稿状态批量改名。

## 统计而不夸大

~~~bash
npm run coverage
~~~

报告区分原文条目数、阅读标点句段数、带草稿释义的条目数、草稿释义总数、独立校勘过的原文条目数。这些数字的统计单位不同，不可以混用为「翻译完成率」。

## 给 Codex / OpenCode 的可执行工作任务

~~~text
请先阅读 docs/EDITORIAL-WORKFLOW.md、docs/TEXTUAL-SOURCES.md、data/volume-*.json 与 data/annotations.js。

这一轮只选择5个尚无释义且语境清楚的重要条目：
1. 保留原文完整不动；不借用未授权的现代译文。
2. 核对说话者、卷、篇、条目编号与相邻问答或书信上下文。
3. 针对确切短句逐条撰写独立的现代解释与误读提醒，状态保持 draft。
4. 逐字证明 quote 存在于同一标点句段，再写入注释文件。
5. 遇疑难文字或语义争议，标注不确定性并创建校勘 Issue。
6. 运行 npm test、npm run coverage、npm run build，附实际结果。
7. 不把所有语句批量生成的摘要称作已校勘的全本白话。
~~~
